// ДОБАВЛЕНИЕ ХОСТА

Нажмите кнопку + на экране хостов, чтобы добавить новый сервер.

Обязательные поля

  • Имя хоста / IP — адрес сервера или IP. Поддерживаются как IPv4, так и IPv6.
  • Порт — по умолчанию 22. Измените его, если на вашем сервере SSH работает на другом порту.
  • Имя пользователя — Unix-пользователь, под которым вы хотите входить (например, ubuntu, root, deploy).
  • Аутентификация — выберите пароль или SSH-ключ (рекомендуется).

Проверка отпечатка хоста

При первом подключении SSHBorg показывает отпечаток сервера и просит вас его принять. Это проверка безопасности: она гарантирует, что вы подключаетесь к нужной машине, а не к самозванцу. Прежде чем принимать, убедитесь, что отпечаток совпадает с тем, который сообщил администратор сервера или который вы получили по доверенному каналу.

После принятия отпечаток сохраняется локально. Если при следующем подключении он изменится, SSHBorg вас предупредит — это может означать переустановку сервера, смену ключей или атаку «человек посередине».

// СОВЕТ
Проверить отпечаток сервера можно в любой момент командой: 
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

// ГРУППЫ ХОСТОВ

Когда список серверов разрастается, хосты можно объединять в сворачиваемые группы с цветовой маркировкой — например Продакшн, Домашняя лаборатория, Клиенты.

Создание группы

  1. Добавьте или отредактируйте хост и откройте выпадающий список Группа.
  2. Выберите Новая группа…, введите название и выберите один из предустановленных цветов.
  3. Сохраните хост — теперь список хостов показывает группу как отдельный раздел.

Работа с группами

  • Свернуть / развернуть — нажмите на заголовок группы, чтобы свернуть или снова открыть её. Состояние запоминается даже после перезапуска приложения.
  • Цвет — цвет группы отображается точкой в заголовке и оттенком значков хостов внутри группы.
  • Изменить — нажмите и удерживайте заголовок группы, затем выберите Изменить, чтобы переименовать группу или сменить её цвет.
  • Удалить — нажмите и удерживайте заголовок, затем выберите Удалить. Хосты в группе не удаляются — они просто перестают быть сгруппированными.

Цвета можно выбрать из быстрых образцов или свободно подобрать с помощью градиентного выбора цвета. У хоста может быть и собственный цвет — он задаётся в редакторе хоста, сразу под группой, — который перекрывает цвет группы и работает также для хостов без группы.

Хосты без группы остаются вверху списка, и если вы никогда не создадите ни одной группы, список будет выглядеть и работать точно так же, как раньше.

// ФАЙЛОВЫЙ МЕНЕДЖЕР SFTP

Файловый менеджер SFTP позволяет просматривать, отправлять, скачивать, переименовывать и удалять файлы на сервере прямо с телефона. Откройте SFTP-сессию с экрана хостов, нажав SFTP.

Навигация

Нажмите на папку, чтобы открыть её. Используйте стрелку назад или нажмите на любой сегмент адресной строки, чтобы подняться вверх по дереву каталогов.

Символические ссылки отмечены маленьким значком ссылки. Нажатие на симлинк переводит к его цели: если он указывает на каталог, вы входите в него, если на файл — он ведёт себя как обычный файл.

Отправка файлов

Нажмите кнопку отправки (↑), чтобы выбрать один или несколько файлов из памяти телефона. Передача начинается сразу, а прогресс отображается вверху экрана.

Скачивание файлов и папок

Нажмите на любой файл, чтобы сразу его скачать. Чтобы скачать папку целиком, нажмите значок скачивания рядом с ней — SSHBorg загрузит всё дерево каталогов и сохранит его в папке Downloads на вашем телефоне.

Если файл уже существует в месте назначения, диалог спросит, нужно ли перезаписать, пропустить файл или отменить всю передачу.

// ПРИМЕЧАНИЕ О СИМЛИНКАХ
При скачивании папки символические ссылки, указывающие на каталоги, пропускаются — загружаются только обычные файлы (включая симлинки на файлы). Это предотвращает непреднамеренную рекурсивную загрузку.

Множественный выбор и групповые операции

Нажмите и удерживайте любой элемент, чтобы войти в режим выбора, затем нажимайте на другие элементы, чтобы дополнить выделение. Панель инструментов показывает действия для текущего выбора:

  • Скачать — скачивает все выбранные файлы и папки сразу, с диалогом прогресса и возможностью отмены.
  • Удалить — удаляет все выбранные элементы. Удаление непустой папки рекурсивно уничтожает всё её содержимое. Отмены нет.

// SSH-КЛЮЧИ

Аутентификация по ключу безопаснее паролей и после настройки не требует ничего запоминать или вводить.

Создание ключа

Перейдите в Настройки → SSH-ключи → Создать новый ключ. SSHBorg поддерживает:

  • Ed25519 — рекомендуется. Быстрый, компактный и безопасный.
  • ECDSA (P-256 / P-384) — хорошая совместимость со старыми серверами.
  • RSA (2048 / 4096 бит) — максимальная совместимость, но медленнее.

Дайте ключу осмысленное имя (например, my-vps или work-server), чтобы потом его узнать.

// ЗАМЕЧАНИЕ О БЕЗОПАСНОСТИ
SSHBorg намеренно не позволяет экспортировать закрытые ключи. Ключ никогда не покидает устройство. Если вам нужен такой же доступ с другого устройства, создайте на нём новый ключ и авторизуйте его на серверах отдельно — так безопаснее.

Авторизация ключа на сервере

После создания ключа нажмите на него, чтобы увидеть открытый ключ. Скопируйте его и вставьте в файл ~/.ssh/authorized_keys на сервере для того пользователя, под которым вы хотите входить.

  1. На телефоне откройте SSHBorg → Настройки → SSH-ключи → нажмите на ключ → скопируйте открытый ключ.
  2. Войдите на сервер (по паролю или другим ключом, который у вас уже есть).
  3. Добавьте открытый ключ в файл авторизованных ключей: 
    mkdir -p ~/.ssh
chmod 700 ~/.ssh
echo "ssh-ed25519 AAAA...вашскопированныйключ..." >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
  4. Попробуйте подключиться через SSHBorg — вход должен пройти без запроса пароля.
// ТРЕБОВАНИЕ К СЕРВЕРУ
Убедитесь, что на сервере в /etc/ssh/sshd_config указано PubkeyAuthentication yes. В большинстве дистрибутивов это значение по умолчанию, но некоторые усиленные образы его отключают.

Дополнительное шифрование ключа

SSHBorg предлагает необязательную дополнительную парольную фразу для ваших ключей (Настройки → SSH-ключи → нажмите на ключ → Включить шифрование). Когда она включена, ключ шифруется парольной фразой, которую SSHBorg не хранит — вводить её придётся при каждом использовании ключа.

Это настоятельно рекомендуется, если вы храните на телефоне доступы к важным серверам или если биометрическая блокировка отключена.

// ПОДСКАЗКИ КОМАНД

Пока вы печатаете в терминале, SSHBorg показывает панель подсказок над клавиатурой. Подсказки берутся из истории команд того пользователя, под которым вы подключились.

Как это работает

При открытии сессии терминала SSHBorg читает файл истории оболочки с удалённого сервера. Он пробует следующие расположения по порядку:

  1. ~/.bash_history — по умолчанию для Bash
  2. ~/.zsh_history — по умолчанию для Zsh (также проверяется $HISTFILE, если задан)
  3. ~/.local/share/fish/fish_history — для пользователей Fish

Используется первый существующий и доступный для чтения файл. По мере ввода команды фильтруются в реальном времени и показываются чипами на панели подсказок. Нажмите на чип, чтобы вставить команду.

Решение проблем

Подсказки не появляются

  • Файл истории может ещё не существовать (первый вход или оболочка не настроена на сохранение истории).
  • Убедитесь, что ваша оболочка настроена на запись истории. Для Bash добавьте в ~/.bashrc: 
    HISTFILE=~/.bash_history
HISTSIZE=10000
HISTFILESIZE=20000
  • Для Zsh добавьте в ~/.zshrc: 
    HISTFILE=~/.zsh_history
HISTSIZE=10000
SAVEHIST=10000
setopt APPEND_HISTORY SHARE_HISTORY

Подсказки от другого пользователя

// ИЗВЕСТНОЕ ОГРАНИЧЕНИЕ
Если вы подключились одним пользователем, а затем выполнили sudo su - root (или переключились на другого пользователя через su), панель подсказок по-прежнему показывает историю исходного пользователя входа, а не root. Это потому, что SSHBorg читает файл истории до запуска оболочки, используя те учётные данные, с которыми вы подключились.

Чтобы получать подсказки из истории root, добавьте в SSHBorg отдельный хост, настроенный на прямой вход под root (если ваш сервер это допускает).

// ЖЕСТЫ В ТЕРМИНАЛЕ

Помимо ввода текста терминал реагирует на несколько сенсорных жестов:

  • Прокрутка истории — проведите вверх или вниз, чтобы просмотреть буфер прокрутки терминала.
  • Масштаб — сведите или разведите пальцы, чтобы уменьшить или увеличить размер текста.
  • Копирование текста — нажмите и удерживайте в любом месте терминала, чтобы войти в режим выделения. Перетаскивайте маркеры, чтобы изменить выделенную область, затем нажмите Копировать выделение, чтобы скопировать только выделенный текст, или Копировать всё, чтобы скопировать весь вывод. Нажмите в любом другом месте для отмены.
  • Вставка — используйте кнопку Вставить на панели дополнительных клавиш (она видна, когда открыта клавиатура).

// НАСТРОЙКИ ТЕРМИНАЛА

В разделе Настройки → Терминал можно подстроить терминал под свои нужды:

  • Цвета терминала — классическая тёмная схема (белое на чёрном), светлая схема (чёрное на белом), которую легче читать при ярком дневном свете, или как тема приложения — она переключается автоматически вместе с темой приложения. Изменение применяется сразу, в том числе к уже открытым сессиям.
  • Не выключать экран — не даёт дисплею гаснуть, пока открыт терминал. Удобно при просмотре логов или длительных команд. По умолчанию выключено.
  • Размер шрифта по умолчанию — размер текста, с которого начинаются новые сессии терминала; масштаб каждой сессии по-прежнему можно менять жестом.
  • Буфер прокрутки, инвертированная прокрутка и подсказки команд — управляют тем, сколько истории вывода сохраняется, направлением прокрутки и панелью подсказок, описанной выше.
  • Действие двойного касания — по желанию двойное касание терминала отправляет Tab (автодополнение) или Tab дважды (показывает все варианты). По умолчанию выключено.

// ПАНЕЛЬ ДОПОЛНИТЕЛЬНЫХ КЛАВИШ

Когда открыта экранная клавиатура, над ней появляется ряд кнопок-ярлыков. Прокручивайте панель вбок, чтобы добраться до всех клавиш.

Клавиши-модификаторы

Ctrl и Alt работают как залипающие переключатели — нажмите одну, затем нажмите букву, чтобы отправить сочетание. Они сбрасываются автоматически после следующего нажатия.

  • Ctrl+C — прервать выполняющийся процесс.
  • Ctrl+D — отправить EOF / закрыть оболочку.
  • Ctrl+Z — приостановить процесс.
  • Ctrl+L — очистить экран.

Режим слов

Значок проверки орфографии переключает клавиатуру между режимом терминала и режимом слов. В режиме терминала (по умолчанию) автозамена и подсказки слов отключены — это идеально для команд и путей к файлам. В режиме слов клавиатура ведёт себя как в обычном текстовом поле, с включёнными подсказками и автозаменой. Полезно, когда вы печатаете обычный текст через SSH, например при работе с Claude Code или другими интерактивными инструментами.

Навигация и редактирование

  • ESC — клавиша Escape.
  • Tab — автодополнение оболочки.
  • ↑ ↓ ← → — клавиши-стрелки курсора.
  • Home / End — переход в начало или конец строки.
  • PgUp / PgDn — страница вверх / страница вниз.
  • Del — удаление вперёд (символ справа от курсора).
  • Вставить — вставить содержимое буфера обмена в терминал.

Функциональные клавиши

Прокрутите панель вправо, чтобы добраться до F1 — F12.

// ПРОБРОС АГЕНТА

Проброс SSH-агента позволяет использовать ключи, хранящиеся в SSHBorg, для аутентификации дальнейших подключений, выполняемых изнутри удалённого сервера — например, чтобы сделать git clone приватного репозитория или перейти на вторую машину.

Включение проброса в SSHBorg

При добавлении или редактировании хоста включите переключатель Проброс агента. SSHBorg будет выступать SSH-агентом для этой сессии.

Настройка на стороне сервера

Сервер должен разрешать проброс агента. Проверьте /etc/ssh/sshd_config:

AllowAgentForwarding yes

В большинстве систем это значение по умолчанию. После изменения перезапустите демон SSH:

sudo systemctl restart sshd

Настройка клиента для конкретного хоста (необязательно)

Если вы подключаетесь к этому серверу ещё и с ноутбука или настольного компьютера, проброс можно настроить постоянно в локальном ~/.ssh/config:

Host myserver
    HostName 203.0.113.42
    User ubuntu
    ForwardAgent yes
// ЗАМЕЧАНИЕ О БЕЗОПАСНОСТИ
Проброс агента даёт удалённому серверу временный доступ к сокету вашего SSH-агента. Пользователь root (или скомпрометированный процесс) на этом сервере может воспользоваться вашими ключами, чтобы подключиться куда-то ещё, пока ваша сессия активна. Включайте проброс только на серверах, которым вы доверяете.

// ПОДДЕРЖКА УСТАРЕВШИХ ШИФРОВ

Некоторые старые серверы — сетевые устройства, встраиваемые системы или машины с устаревшими версиями OpenSSH — поддерживают только те алгоритмы шифрования, которые современные SSH-клиенты больше не предлагают по умолчанию.

Когда вы включаете переключатель Разрешить устаревшие шифры в настройках хоста, SSHBorg добавляет в список согласования следующие дополнительные алгоритмы:

Добавляемые алгоритмы

  • Шифры: aes128-cbc, aes192-cbc, aes256-cbc, 3des-cbc
  • Обмен ключами: diffie-hellman-group14-sha1, diffie-hellman-group-exchange-sha1, diffie-hellman-group1-sha1
  • Тип ключа хоста: ssh-dss (DSA 1024 бит)

Сервер всегда согласует самый стойкий алгоритм, поддерживаемый обеими сторонами, поэтому включение этой опции не ослабляет подключения к современным серверам — устаревшие алгоритмы используются только тогда, когда сервер не может предложить ничего лучше.

// ЗАМЕЧАНИЕ О БЕЗОПАСНОСТИ
Алгоритмы из этого списка считаются криптографически слабыми. Включайте эту опцию только для серверов, которые вы не можете обновить.

// ОБРЫВЫ СОЕДИНЕНИЯ И ТЕРМИНАЛЬНЫЕ МУЛЬТИПЛЕКСОРЫ

SSH — это живое TCP-соединение между вашим телефоном и сервером. Если соединение прервётся — пусть даже на секунду — сессия и всё, что в ней выполняется, будет потеряно.

Почему на мобильных соединения обрываются

Мобильные сети особенно склонны к обрывам по нескольким причинам:

  • Смена IP-адреса — в поездке или при переключении между сотовыми вышками оператор может выдать вам новый публичный IP. Поскольку TCP-соединения привязаны к IP-адресу, существующая SSH-сессия сразу становится недействительной.
  • Переход Wi-Fi ↔ мобильная сеть — переключение между Wi-Fi и мобильными данными (или наоборот) меняет ваш IP и разрывает любое открытое TCP-соединение.
  • Тайм-ауты простоя — операторы и NAT-маршрутизаторы часто разрывают неактивные соединения через несколько минут. Долгие, но «молчаливые» сессии (просмотр логов, ожидание ввода) особенно уязвимы.
  • Потеря сигнала — туннели, подземные парковки или просто слабый сигнал могут ненадолго уронить сеть, и этого достаточно, чтобы убить сессию.
// ВАЖНО
Если вы выполняете длительную команду (сборку, резервное копирование, миграцию базы данных) прямо в SSH-терминале и соединение обрывается, команда немедленно завершается. Частично выполненная работа может остаться в несогласованном состоянии.

Решение: tmux или screen

Терминальный мультиплексор запускает постоянную сессию на сервере, полностью независимую от вашего SSH-соединения. Если связь оборвётся, сессия и всё, что в ней выполняется, продолжит работать. Переподключившись, вы снова присоединяетесь к ней и находите всё ровно там, где оставили.

Это самая полезная привычка для всех, кто управляет серверами с телефона.

Быстрый старт с tmux

tmux доступен в большинстве современных дистрибутивов Linux и является рекомендуемым вариантом.

# Запустить новую именованную сессию
tmux new -s work

# Отсоединиться от сессии (оставить её работать)
Ctrl+B, затем D

# Показать список запущенных сессий
tmux ls

# Снова присоединиться к сессии
tmux attach -t work

# Присоединиться к самой последней сессии
tmux attach

Быстрый старт со screen

screen старше, но доступен практически в любой Unix-системе, включая минимальные серверные образы, где tmux может быть не установлен.

# Запустить новую именованную сессию
screen -S work

# Отсоединиться от сессии
Ctrl+A, затем D

# Показать список запущенных сессий
screen -ls

# Снова присоединиться к сессии
screen -r work

Рекомендуемый порядок работы на телефоне

  1. Подключитесь к серверу через SSHBorg.
  2. Сразу запустите или присоедините сессию tmux/screen: tmux attach || tmux new -s main
  3. Выполняйте команды внутри мультиплексора.
  4. Если соединение оборвётся, просто переподключитесь — ваша сессия на месте.
// СОВЕТ
Можно добавить tmux attach || tmux new -s main в ~/.bashrc или ~/.zshrc на сервере, чтобы сессия мультиплексора запускалась автоматически при каждом входе через SSHBorg.

// JUMP HOSTS

Jump host (его также называют бастионом) — это промежуточный сервер, через который нужно пройти, чтобы добраться до целевого сервера, недоступного из интернета напрямую. SSHBorg изначально поддерживает одиночные и многозвенные цепочки переходов.

Настройка jump host в SSHBorg

  1. Добавьте сервер-бастион как обычный хост в SSHBorg (например, bastion).
  2. Добавьте целевой сервер как ещё один хост.
  3. В настройках целевого хоста укажите в поле Jump host созданный вами бастион.
  4. Включите Проброс агента на записи бастиона — это позволит пробросить ваш ключ через бастион для аутентификации на целевом сервере.
// КАК ЭТО РАБОТАЕТ
SSHBorg сначала устанавливает SSH-соединение с бастионом, а затем открывает через него проброшенный TCP-канал к целевому серверу. Ваш закрытый ключ никогда не покидает телефон — бастион лишь проксирует зашифрованный поток.

Многозвенные цепочки

Если нужно пройти более чем через один промежуточный сервер (например, интернет → bastion → dmz → target), создайте запись для каждого звена и свяжите их:

  • bastion — без jump host, проброс агента включён
  • dmz — jump host = bastion, проброс агента включён
  • target — jump host = dmz
// ВАЖНО
Проброс агента должен быть включён на каждом промежуточном звене, а не только на первом. Без этого цепочка аутентификации разрывается, и подключение к конечному серверу завершится ошибкой «permission denied».

Эквивалентная ручная настройка (для справки)

Аналогичная конфигурация в настольном ~/.ssh/config выглядит так:

Host bastion
    HostName bastion.example.com
    User admin
    ForwardAgent yes

Host target
    HostName 10.0.1.50
    User ubuntu
    ProxyJump bastion
    ForwardAgent yes

С такой конфигурацией команда ssh target на ноутбуке прозрачно проходит через бастион.

Требования к межсетевому экрану

  • Ваш телефон должен иметь доступ к бастиону по его SSH-порту (обычно 22).
  • Бастион должен иметь доступ к целевому серверу по его SSH-порту.
  • Целевой сервер не обязан быть доступен напрямую с вашего телефона.

// НЕСКОЛЬКО СЕССИЙ

SSHBorg позволяет держать открытыми одновременно несколько сессий SSH-терминала и файлового менеджера SFTP, даже к разным серверам.

  • Откройте сессию с экрана хостов, нажав Терминал или SFTP.
  • Переключайтесь между открытыми сессиями через селектор сессий вверху экрана.
  • Сессии остаются активными в фоне, пока держится сетевое соединение.
  • В списке хостов рядом с каждым хостом показывается небольшой значок с количеством активных SSH- и SFTP-сессий, так что с одного взгляда видно, что открыто.
// СОВЕТ
Длительные команды (сборки, резервные копии, просмотр логов) продолжают выполняться, даже когда вы переключаетесь на другую сессию. Используйте на сервере терминальный мультиплексор вроде tmux или screen, если хотите, чтобы они пережили и обрыв SSH-соединения.

// БЕЗОПАСНОСТЬ ПРИЛОЖЕНИЯ

Биометрическая блокировка

Включите биометрическую блокировку в Настройки → Безопасность → Биометрическая блокировка. Когда она активна, SSHBorg требует отпечаток пальца или распознавание лица, прежде чем показать любые хосты, учётные данные или данные сессий.

Можно задать тайм-аут бездействия — по истечении заданного числа минут в фоне приложение блокируется автоматически.

Защита от скриншотов

По умолчанию SSHBorg блокирует скриншоты и запись экрана, чтобы конфиденциальное содержимое терминала не утекло через экран недавних приложений или инструменты захвата экрана.

Если вам нужно сделать скриншот (например, чтобы поделиться выводом терминала), защиту можно временно отключить в Настройки → Безопасность → Разрешить скриншоты.

Хранение учётных данных

Все учётные данные (пароли, закрытые ключи, парольные фразы) хранятся в зашифрованном виде с использованием Android Keystore — аппаратно защищённого хранилища, доступного на Android 10+. Они никогда не записываются во внешнюю память и никуда не передаются.

// ЗАМЕЧАНИЕ О РЕЗЕРВНОМ КОПИРОВАНИИ
Поскольку ключи хранятся в Android Keystore, их нельзя включить в резервную копию через механизм облачного бэкапа Android, и они не перенесутся на новый телефон автоматически. Перед сменой устройства обязательно авторизуйте на всех своих серверах новый ключ, созданный на новом устройстве.

// РЕЗЕРВНАЯ КОПИЯ НАСТРОЕК

SSHBorg умеет экспортировать и импортировать конфигурации хостов в виде JSON-файла. Это позволяет перенести список серверов на другое устройство или хранить переносимую копию своей конфигурации.

// ВАЖНО
Резервная копия содержит только конфигурации хостов (адрес, порт, имя пользователя, настройки). Пароли и SSH-ключи никогда не экспортируются — их придётся настроить заново после импорта на новом устройстве.

Экспорт

Перейдите в Настройки → Резервная копия → Экспорт хостов. Выберите, куда сохранить файл, с помощью системного диалога. По умолчанию файл называется sshborg_hosts.json.

Импорт

Перейдите в Настройки → Резервная копия → Импорт хостов. Выберите ранее экспортированный (или созданный вручную) файл .json. SSHBorg объединит его с существующим списком хостов:

  • Хосты, чья метка совпадает с существующей записью, обновляются.
  • Хосты с новой меткой добавляются.
  • Хосты, отсутствующие в файле, остаются без изменений.

Формат JSON

Файл экспорта — это обычный объект JSON. Его можно создать и вручную, чтобы массово импортировать список серверов из другого источника.

{
  "version": 2,
  "exported_at": "2026-05-14T10:00:00Z",
  "groups": [
    { "name": "Продакшн", "color": -1754827 }
  ],
  "hosts": [
    {
      "label":           "Мой VPS",
      "hostname":        "203.0.113.42",
      "port":            22,
      "username":        "ubuntu",
      "agentForwarding": false,
      "jumpMode":        "simple",
      "jumpHosts":       null,
      "jumpHostIdList":  null,
      "portForwardings": null,
      "sftpStartMode":   "last",
      "sftpStartDir":    null,
      "allowLegacyCiphers": false,
      "group":           "Продакшн"
    }
  ]
}

Описание полей

  • label — отображаемое имя в SSHBorg. Используется как уникальный ключ при объединении во время импорта. Обязательное.
  • hostname — адрес сервера или IP (IPv4 или IPv6). Обязательное.
  • port — SSH-порт. По умолчанию 22.
  • username — пользователь для входа. Обязательное.
  • agentForwarding — true, чтобы включить проброс SSH-агента. По умолчанию false.
  • jumpMode — "simple" (использовать текст jumpHosts) или "host_list" (использовать внутренние идентификаторы хостов SSHBorg). При создании файла вручную используйте "simple".
  • jumpHosts — промежуточные хосты через запятую в формате [user@]host[:port]. Используется только когда jumpMode равен "simple".
  • portForwardings — правила локального проброса портов, по одному на строку, в синтаксисе SSH -L, например "8080:localhost:8080".
  • sftpStartMode — начальный каталог SFTP: "last" (запоминать последний посещённый), "fixed" (всегда использовать sftpStartDir), "home" (домашний каталог на сервере). По умолчанию "last".
  • sftpStartDir — путь, используемый когда sftpStartMode равен "fixed".
  • allowLegacyCiphers — true, чтобы включить устаревшие алгоритмы шифрования, описанные выше. По умолчанию false.
  • group — имя группы, к которой принадлежит хост. Группы перечисляются в массиве groups верхнего уровня с полями name и color (ARGB как знаковое 32-битное целое). Если хост ссылается на группу, которой нет в массиве, она создаётся автоматически с цветом по умолчанию — поэтому при написании файла вручную массив можно вообще опустить.
  • color — необязательный собственный цвет хоста (ARGB как знаковое 32-битное целое). Он перекрывает цвет группы.
// НЕОБЯЗАТЕЛЬНЫЕ ПОЛЯ
Все поля, кроме label, hostname и username, необязательны. Пропущенные поля принимают значения по умолчанию.
